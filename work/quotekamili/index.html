QuoteKamili

Quote requests in any format become complete, priced quotes in under a minute, and every price is calculated in tested code rather than by the model.

The problem

Electrical, plumbing and HVAC distributors in the UK and US get requests for quotes in every format: emails, PDF purchase orders, photos of handwritten lists, bid sheets. Turning each one into a priced quote means hours of retyping lines and looking them up in the supplier's catalogue.

The obvious shortcut is to hand the whole request to a language model. But a quote is a commitment to a price. A model that misreads a unit or miscounts a total, or that sees a supplier's pricing, is a risk a distributor can't take.

What I built

  • An AI pipeline that reads requests in any format (emails, PDF purchase orders, photos of handwritten lists, bid sheets) and matches each line to the supplier's catalogue.
  • Pricing in tested code. Prices, totals and unit conversions never come from the model, and supplier pricing is never sent to one.
  • Source tracing and review. Every quote line links to its place in the source document, and a rep approves each quote before it goes to a customer or the ERP.
  • A multi-tenant platform on AWS (ECS Fargate, RDS PostgreSQL with pgvector, CDK) with row-level security in the database.
  • Idempotent background jobs, so a retry never creates a duplicate quote or charge.
  • Property-based tests (fast-check) on pricing and credit rules, and UI tests in real Chromium, WebKit and Firefox across time zones with Vitest, Playwright and axe-core.
  • One React codebase, shipped to web, to iOS and Android through Capacitor, and to desktop through Tauri.

How it works

Key decisions

  1. The model reads; code prices

    Instead ofLetting the model produce prices and totals

    The model only extracts what the customer asked for. Prices, totals and unit conversions run in code covered by property-based tests, so the same request always gets the same price, and supplier pricing is never sent to a model.

  2. A person approves every quote

    Instead ofSending quotes out automatically when extraction looks confident

    Every quote line links to its place in the source document, so a rep can check each line against what the customer actually wrote. Nothing reaches a customer or the ERP until a rep approves it.

  3. Tenant isolation in the database

    Instead ofFiltering by tenant in application code only

    A supplier's catalogue and pricing are the most sensitive data in the system. Row-level security in PostgreSQL enforces isolation in the database itself, so one missed filter in application code can't expose another tenant's data.

  4. Idempotent background jobs

    Instead ofAssuming each job runs exactly once

    Background jobs get retried after timeouts and failures. Every job is idempotent, so a retry never creates a duplicate quote or charge.

Results

Requests that took hours of retyping become complete, priced quotes in under a minute. Every price comes from tested code, every line can be traced back to the customer's document, and nothing goes out without a rep's approval.
